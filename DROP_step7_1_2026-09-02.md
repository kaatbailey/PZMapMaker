## The delivery lessons from this drop, since they cost real time

**Copy first, THEN touch, across BOTH repos.** A file copied in after the
`touch` arrives with its future mtime intact and Ninja loops
`manifest 'build.ninja' still dirty after 100 tries`. An extension glob is the
wrong instrument — it misses `.java` and cannot reach the other repo:

```fish
find ~/Documents/PZMapMaker ~/Documents/PZMapCreation -not -path '*/.git/*' \
     -type f -newermt now -exec touch {} +
find ~/Documents/PZMapMaker ~/Documents/PZMapCreation -not -path '*/.git/*' \
     -type f -newermt now      # must print nothing
```

Then **delete the build directory rather than reconfiguring into it** — its
`build.ninja` has already recorded the future stamps.

**Check for `(1)` suffixes.** A browser download onto an existing filename
produces `TreePalette (1).java`, `javac` refuses it (public class must match the
filename), the compile fails, and `java` then runs happily on STALE `.class`
files. That happened on the previous drop and looked like a successful run.

```fish
command ls ~/Documents/PZMapMaker | command grep -F '('
```

**`javac` being silent is the gate.** A failed compile followed by a successful
`java` invocation is the same shape as the Ninja failure: a tool reports trouble
and a stale artefact runs anyway.

**`wc -l` both copies of any Java oracle.** The copy into `PZMapCreation` is the
step most likely to be skipped, because it is the one that leaves a repo.
